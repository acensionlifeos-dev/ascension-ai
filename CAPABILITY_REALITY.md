# Ascension AI Capability Reality

This document preserves Devin's full Ascension AI roadmap while separating what is production-real now from what still needs an engine or an authenticated product shell.

## Active in the native core

- Natural, shell-specific conversation for AP, LifeOS, NexusHome, and NexusFamily
- Permission-scoped context interpretation and life-domain routing
- Deterministic retrieval over memories, documents, knowledge, and evidence supplied with a request
- Explicit memory candidates for the calling shell to validate and persist
- Schedule shorthand interpretation, including inclusive day ranges
- Finance, housing, nutrition, learning, career, creation, health, and family action planning
- Missing-variable detection so plans ask only for facts that change the outcome
- Action risk classification and explicit-confirmation boundaries
- Multilingual reasoning through the selected native model

## Active when the Ascension shell supplies the connection

- Web research and current information
- Vision and image understanding
- Voice transcription and playback
- Calendar, email, social, finance, and other external actions
- Durable personal memory, corrections, receipts, and cross-surface updates

The native core proposes and explains. The authenticated shell checks identity, tier, consent, permissions, and current connection state; executes the action; records the receipt; and reports the real result. This keeps AP powerful without allowing an isolated model to impersonate successful actions.

## Preserved roadmap, not yet production-proven

- Native image, audio, and video generation
- Large-scale autonomous web exploration
- Trained multimodal Ascension foundation models
- Distributed training and continual model improvement
- Hardware, robotics, AR, and real-time environmental perception

Devin's architecture and ambition remain part of the project. A roadmap capability moves into the active list only when its engine, safety boundary, tests, and product surface all work together.
