# Ascension engineering coordination

Before editing this repository, read and follow the permanent coordination issue:

https://github.com/acensionlifeos-dev/AscensionLifeOS/issues/40

Required for every Codex, Devin, or other implementation-agent run:

1. Fetch `origin/master` and inspect the working tree before editing.
2. Comment on issue #40 with the Ascension AI objective, files claimed, and evaluation plan.
3. Never force-push or overwrite another worker's changes.
4. Preserve shell isolation, permission-scoped context, receipt discipline, action approval, private-data boundaries, and the native replacement gates in issue #40.
5. Do not describe a prompt, stub, or future-work note as an active ability.
6. Run `python scripts/replacement_contract_eval.py` and `python -m compileall -q src scripts` before pushing.
7. Post the commit, evaluation counts, Render status, production evidence, and remaining blocker to issue #40.

Keep outside-AI fallback available until all native replacement gates are proven. External data and action providers remain authoritative tools of the authenticated Ascension shell.

## Native model training priority

Training must serve Ascension needs first, then broaden. The native model must master the LifeOS, HomeOS, Sprout, FamilyOS, AP, and Ascension product domains before adding general-world breadth. Do not chase general benchmarks at the expense of the specific tasks Ascension users will depend on. Broaden only after the core product surface is proven.
